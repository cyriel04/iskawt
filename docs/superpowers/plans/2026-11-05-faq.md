# FAQ Section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Questions" accordion section at the bottom of the browse page, anchored at `#faq`, linked from the footer.

**Architecture:** Copy is plain data in `app/_lib/constants/faq.ts`. A server component `FaqSection` renders it as MUI `Accordion`s in two groups. The browse page mounts it below `BrowseView`; `SiteFooter` links to `/#faq`.

**Tech Stack:** Next.js 16 App Router, MUI 9 (`Accordion`, `AccordionSummary`, `AccordionDetails`, `Typography`), SCSS modules, Jest + RTL.

**Spec:** `docs/superpowers/specs/2026-11-05-faq-design.md` — the copy there is approved and is copied verbatim.

## Global Constraints

- Owner: frontend-dev for every file. `faq.ts` is a new file in shared constants (an addition).
- SCSS modules only, tokens via `@use "../_styles/tokens" as *;`. No `sx`, `styled()`, `style={{}}`, raw hex or literal spacing.
- No new dependency. No change to `app/_lib/types.ts`, the schema, or any API.
- Server components; no `"use client"` in new files.
- Product name is "Iskawt", always.
- Copy is the spec's, word for word. The sign-in answer builds "15" from `MAGIC_LINK_TTL_MINUTES` (`app/_lib/constants/limits.ts`).
- Commit at each task's end, message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never stage `AGENTS.md`.

## Review Focus

1. **Empty results** — no spaces match the filters: the FAQ still renders under the empty state. (Task 2 test.)
2. **`/#faq` after streaming** — the browse page streams behind `loading.tsx`; visiting `/#faq` must land on the section. Manual check in `pnpm dev` (Task 2 Step 6).
3. **Keyboard** — Tab to a question, Enter opens it, answer becomes visible; `aria-expanded` flips. (Task 1 test.)
4. **Heading outline** — `h2` "Questions", `h3` per group, `h4` per question; screen readers jump by heading. (Task 1 test.)
5. **Shared items stay in sync** — the two "both" items are one object each, referenced from both groups, never duplicated text. (Task 1 test.)

### Task 1: FAQ copy and `FaqSection` component

The two shared items are module-level constants (`SIGN_IN`, `REPORT_OR_BLOCK`) placed last in both groups.
  - `FaqSection.tsx`: `export default function FaqSection({ groups = FAQ_GROUPS }: { groups?: readonly FaqGroup[] })` → `<section id="faq" aria-labelledby={…}>` with `h2` "Questions", an `h3` per group, an MUI `Accordion` per item whose summary heading is `h4` (MUI 9: `slots={{ heading: "h4" }}` — confirm in `node_modules/@mui/material/Accordion/Accordion.d.mts`), collapsed by default. Give each summary/details a stable id pair from `useId` or group/item index so `aria-controls` resolves.
